05 / THE BUILD LOOP

真正好用的 Vibe Coding 工作流

不是"一句话让 AI 帮我写代码"，而是有节奏、有阶段、有反馈的小闭环。每一步都让下一个环节更轻松，循环推进。这是一个可复用的流程（Repeatable Process）。

定义问题

清晰、具体、可验收

写需求档

功能描述 · 数据结构 · 交互逻辑

拆分任务

小步提交 · 每步可回退

生成页面

先做所有页面，逐步调整

迭代细化

测一遍 · 改一遍 · 再测一遍

交付上线

部署 · 域名 · 收集反馈

一次没生产出有需求才交给 AI

不要一开始就"给我做个 App"。先写清楚：用户是谁、做什么、页面有哪些、数据存哪里。需求描述越清楚，生成越稳定。改需求时也一样：一次只改一件事，改完测一遍再继续。

先做最重要的核心闭环

先用最短路径让产品"能用"：一个页面能提交、能看到结果。再补登录、再补美化。不要一上来就做权限、做支付——先把核心闭环跑通，再一轮一轮往外扩。

06 / PROJECT STUDIO

项目实战：从小作品到完整产品

1 个 Hands-on Project。按顺序做，每完成一个项目，你的工作流就更熟练一次。

PROJECT 01

单页小游戏 / 交互小工具

最经典的第一个项目：规则明确、纯前端、当天可完成。重点练习"描述清楚 → 生成 → 调整"的循环。

单文件HTML/CSS/JS1 天

要做的准备：

· 选一个你真的想玩的小游戏或小工具
· 写 3 句话需求（是什么 / 怎么玩 / 怎么算赢）

07 / TOOLS & STACK

工具与技术栈

按项目阶段选工具，不追新、不堆栈。

AI 编程工具

Claude Code · 终端 Agent，适合整套项目与重构
Cursor · AI IDE，边写边改体验好
Codex / Cline · 轻量替代，按需选择

前端

HTML / CSS / JavaScript 起步；组件化用 React + Tailwind；需要快速上线直接用 Vite。

后端与数据

Supabase（数据库 + 登录 + 存储，最适合个人项目）；复杂逻辑再上 Node/Python 服务。

部署

Vercel / Netlify 一键部署前端；自定义域名 + HTTPS；生产数据库单独管理。

08 / PROMPT LIBRARY

可直接拿去用的 Prompt 模板

复制、替换方括号里的内容，直接发给 AI。每个模板都标了使用时机。

01 / 先帮我做决策
我想做一个【一句话描述产品】。请先不要写代码，帮我回答：1. 最小可用版本（MVP）应该包含哪 3 个功能？2. 哪些功能第一版不该做？3. 数据需要存哪些字段？用表格回答。
02 / 生活方向守卫 PRD
请根据以下描述，帮我整理一份一页纸 PRD，包含：产品一句话、目标用户、核心场景、功能清单（分 P0/P1）、页面结构、数据结构。产品描述：【粘贴你的想法】。
03 / 先想限制，不要动代码
这是我现在的代码：【粘贴代码】。报错信息是：【粘贴报错】。请先只分析可能的原因（按概率排序），不要直接改代码。等我确认原因后再修复。
04 / 改需求只改一件事
请在现有项目上只做这一处修改：【描述改动】。不要动其他文件的逻辑。改完后告诉我：改了哪些文件、如何验证这次改动生效。
05 / Debug：不允许你别猜
程序出现【描述现象】。请给出 3 个最可能的原因和对应的验证方法（每条一个可执行的检查命令/步骤），我来逐条验证后再修复。
06 / 上线前用户守备复查
请以资深审查者身份检查这个项目：1. 安全问题（密钥泄露、权限漏洞）2. 明显 bug 3. 移动端适配 4. 性能隐患。按严重程度排序输出清单，先不要改代码。

常见问题排查手册

遇到问题先对号入座，大多数问题都是这几类。

界面没变化 / 改老

改的是旧文件、没保存、或浏览器缓存 → 强刷（Ctrl+Shift+R），确认 AI 改的文件就是正在运行的文件。

Module not found

包没装或路径写错 → 看报错里的包名，npm install；检查 import 路径大小写。

API 401 / 403

密钥没配、配错环境、或没加到服务器端 → 检查 .env 与调用位置（密钥不能出现在前端）。

改 A 坏 B（回归）

改动面太大 → 回退到上一个 commit，把需求拆小，一次只改一件事。

09 / QUALITY GATE

项目交付前，逐项打勾

这套检查清单为了防止"看起来能用"的产品一路带病上线。每一项都是别人踩过的坑，勾完再交付。

✓
需求没跑偏
核心功能与 PRD 一致，没有偷偷加/漏功能。
✓
核心流程走得通
从打开 → 使用 → 拿到结果，全程无阻断。
✓
空状态/异常提示
没数据、网络失败、输错时有友好提示。
✓
手机能用
在手机浏览器打开核心页面检查布局。
✓
密钥不在前端
API key 只在服务端/环境变量，代码仓库里没有明文密钥。
✓
数据能保存
刷新/重启后用户数据还在。
✓
回退方案
git 有干净提交，出问题能回退到上一个版本。
✓
上线地址可访问
部署链接（Vercel 等）打开正常，HTTPS 生效。
✓
找真实用户试过
至少 1 个目标用户完整用过一次，收集了反馈。

⚠️ 安全提示：不要在浏览器端保存 API key，也不要把生产数据库的管理员权限交给前端页面。

常用技术词典

不用一次性背下来，用到时回来查就行——所有术语会在它们出现的位置再解释一遍。

MVP

最小可行产品：能验证想法的最简版本。

PRD

产品需求文档：写清楚做什么、给谁用。

API

程序之间对话的接口，AI 能力靠它接入。

HTML

网页的骨架，决定页面上有什么。

CSS

网页的皮肤，决定长什么样。

JavaScript

网页的行为，让它动起来、能交互。

组件 Component

可复用的界面积木，如按钮、卡片。

State

页面当前的数据状态，变了界面就变。

Repo

代码仓库，项目的全部历史与版本。
